# 智能剪辑 V2 — 批量剪辑功能开发文档

> 日期：2026-06-11
> 范围：基于现有 CLIP V2 视觉剪辑，新增批量模式（5~8 段/次）
> V1 (`clipper.py`)：不修改，已停用

---

## 1. 需求背景

当前 CLIP V2 每次只产出 **1 个** 剪辑后视频（15~30s）。用户上传一段中长视频，需要手动多次调整描述才能获得多个片段。目标：一次上传，批量产出 **5~8 个不雷同的 15~20s 短视频**。

### 需求清单

| # | 需求 | 状态 |
|---|------|------|
| 1 | 一次 GLM 调用返回 5~8 个片段 | ✅ |
| 2 | 每个片段 15~20s，GLM 返什么裁什么 | ✅ |
| 3 | 片段不百分百雷同即可 | ✅ |
| 4 | 去重以 FB/TikTok 平台不判定重叠为准 | ✅ |
| 5 | 不够 5 段时从未使用区域自动补段 | ✅ |
| 6 | 短影片保护：自动计算最大可行段数 | ✅ |
| 7 | 批量采样比单视频更密，动态非固定步长 | ✅ |
| 8 | 前端新增「单视频剪辑 / 批量剪辑」切换 | ✅ |
| 9 | 批量模式隐藏时长选择器 | ✅ |
| 10 | 逐个下载链接（不打包 zip） | ✅ |
| 11 | API 加 `mode` 参数区分，不开新路由 | ✅ |
| 12 | V1 不修改 | ✅ |

## 3. 采样策略

### 单视频模式（不改）

| 时长 | step 计算 | 帧数 |
|------|-----------|------|
| ≤60s | 固定 3s | ≤20 |
| >60s | `max(10.0, duration / 15.0)` | — |

### 批量模式（新增 `sample_timestamps_batch`）

```
target = min(50, max(25, int(duration / 6)))
step = max(duration / target, 2.5)
```

| 时长 | 目标帧数 | step | 与单视频对比 |
|------|---------|------|------------|
| 60s | 25 | 2.5s | 单: 20帧 step=3s |
| 180s | 30 | 6.0s | 单: 12帧 step=15s |
| 300s | 50 | 6.0s | 单: 15帧 step=20s |
| 600s | 50(cap) | 12.0s | 单: 40帧 step=15s |

核心：**批量只有一轮、不需要重试**。不足 5 段走 Python 补段兜底。

---

## 4. 去重逻辑（`_dedup_segments`）

按平台去重标准：两段视频**连续相同帧不能多**。

```
1. 按 start_sec 排序
2. 遍历相邻段：
   a. 重叠比例 > 30% → 丢弃当前段
   b. 重叠比例 ≤ 30% → 修剪起点 = prev.end + 3s
   c. 间隙 < 3s → 强行拉开
3. 修剪后长度 < 12s → 丢弃
4. clamp 到 15~20s 边界
```

---

## 5. 补段逻辑（`_fill_segments`）

去重后不足 5 段时触发：

```
1. 构建未使用时间区域
2. 按长度降序排序
3. 从最长可用区域取中点，截 17s 段
4. 重复直到补满或无可补区域
```

补出的段标注 `reason: "自动补充片段"`。

## 6. GLM Prompt 设计

### 单视频（不改）

```
找出最符合的一个时间段 → 输出单个 JSON 对象
```

### 批量（新增）

```
你是一个视频剪辑助手。从一段长视频中提取多个短视频片段。

【剪辑指令】{description}
【每段时长】15~20 秒
【输出数量】5~8 段

请从帧序列中选出 5~8 个适合独立成片的片段：
1. 优先匹配剪辑指令的画面区域
2. 不够时补充视觉精彩画面：表情变化、冲突辩论、文字标题、爆料瞬间、场景切换
3. 覆盖影片的**不同时间段**，不要全部集中在一处
4. 相邻片段间隔至少 3 秒

输出 JSON 数组（仅 JSON）：
[{"start_sec": 30, "end_sec": 48, "reason": "表情变化明显"}, ...]
```

## 7. API 变更

### `POST /api/clip_v2` — 加 `mode` 参数

**单视频**（默认）：
```
mode: "single"   ← 新增，默认值
duration: 20     ← 不变
```

返回（不变）：`{ status, filename, download_url, ... }`

**批量**：
```
mode: "batch"    ← 新增
```

返回：
```json
{
  "status": "ok",
  "clips": [
    { "filename": "clip_xxx_01.mp4", "download_url": "/api/...", "reason": "...", ... },
    ...
  ],
  "total": 6
}
```

### 短影片保护

```
max_segments = floor(duration / 17)   # 17 = min_len(15) + min_gap(2)
if max_segments < 5: 前端提示「建议上传 5 分钟以上」
```

## 9. Token 消耗预估

| 指标 | 单视频模式 | 批量模式 |
|------|-----------|---------|
| GLM 调用次数 | 1~2 次 | 1 次 |
| 采样帧数（300s） | 15 帧 | 50 帧 |
| 推估总 Token | ~1,400~2,000 | ~3,700~4,800 |
| 产出片段数 | 1 段 | 5~8 段 |
| **每段均摊 Token** | ~1,400~2,000 | **~460~960** |
